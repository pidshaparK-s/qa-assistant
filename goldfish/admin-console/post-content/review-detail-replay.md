## Testability flags
- TF1 R6, R15, R30, R7 — time windows and scheduler firing; the cutoff is console-side, so it runs on the browser clock and a tester can shift it, but Failed and "already published" need the real scheduler to fire on staging — generic lenses *Time*, *Async*. Ask: does staging run the AWS scheduler, and what is the lag?
- TF2 R10, S-R10-4/5 — filling the limit on a shared network collides (TC-NETWORK-SETTING). `postScheduler.limit` is per network (core `src/services/v1/post-scheduler.service.ts:81`) → a dedicated network with a low limit. The limit is absent from the payload the console reads, so the case must name the value out of band.
- TF3 R10 blocked word / blocked link — the network blocklist is shared (TC-NETWORK-SETTING); the case names the network.
- TF4 R31, R21, R14 — one network per entitlement state under `enforce`, plus `shadow`/`off` for S-R31-2; console-next itself is closed when entitlement is off/absent (TC-ENTITLEMENT-GATE) → the stub, or named networks.
- TF5 R11, R36, S-R11-1/2 — two admins at once; shared session on staging (TC-SHARED-SESSION) → two profiles, two accounts.
- TF6 §4 — every role row needs a standing custom role (TC-ADMIN-ROLE-PERMANENT), including one that core refuses on approve (QF32) and one for each pin flag (QF33).
- TF7 R25 / QF34 — revocation means editing a shared role (TC-PERMISSION-REVOKED).
- TF8 R18, R19 "Logged" and "deleted by AI" — AI moderation not provisioned on staging (TC-AI-MODERATION) → seeded data or manual.
- TF9 R13, R37 (S-R13-1, S-R37-2) — the Then is in the UIKit and the owner's notification tray: cross-product, needs a UIKit build and the owner's account — generic lens *Cross-product*.
- TF10 R6, R32 (scheduled edit), S-R6-1..3 — `PUT /admin/v1/posts/schedule/:id` is **missing** (§5, SL-00). Every reschedule and scheduled-edit case is blocked until core lands the alias.

- TF12 QF1/QF2 — needs a group with `needApprovalOnPostCreation` and an admin role without review permission (a network setting plus a standing role).
