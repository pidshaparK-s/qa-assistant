Close the Live Stream Activation Funnel — before, during, and after the event

🎨 Figma Design: Notification Tray — Event creation notification

💡 Opportunity Brief
- What: Ensure the event creation notification tray item deep-links directly to the event RSVP page, so members can RSVP in a single tap.
- Who it's for: Community members on networks running live stream activations.
- Why it matters: The existing creation tray notification ("You've been invited to an event") already deep-links to the event detail page, where the RSVP action is already visible. The remaining gap is improving the information scent and relevance of the tray item (richer details, correct context like livestream indicator) so members are more likely to tap and RSVP.
- Expected outcome: Higher tap-through and RSVP rates driven by richer event details in the tray item (while keeping the destination as the event detail page).

📋 Release Note

Events: Notification Tray — Richer event details + one-tap to RSVP

Event creation notifications now show the event name, date, and start time so members know exactly what they're being invited to before they tap. Tapping navigates directly to the event RSVP page.

💡 Idea

Update the NotificationTrayItem generated on event creation to:

  1. Show richer content — replace the generic "You've been invited to an event" with the event name, date, start time, and community name
  1. Deep-link to RSVP — tapping navigates directly to the event RSVP page
  1. Add an event-type chip — show a pill chip indicating In-person or Virtual so members understand the event format at a glance
  1. Do not group notifications — each event creation generates its own distinct tray item, even if multiple events come from the same community

Also confirm and enforce:

  • Community membership scoping (members only, excluding banned)
  • Private community events not surfaced to non-members
  • Graceful handling when the event is deleted before the notification is tapped

Recommended copy pattern (from competitor research + design):

Primary line:   {{CommunityName}} has event {{EventName}}
Secondary line: [EventType chip]  {{EventStartDate}} · {{EventStartTime}}

Example: "Ulta Beauty Community has event Ulta Beauty World Masterclass 2026" / [In-person] 10 Jul 2026 · 7:00 PM

{{EventType}} renders as a pill/chip label: In-person for in-person events, Virtual for virtual/livestream events.

{{EventStartDate}} and {{EventStartTime}} refer to the scheduled start of the event (not current time).

💭 Problem Definition

What problem are we solving?

The event creation tray notification fires today and the tap-through lands on the event detail page, where the RSVP action is already visible. The remaining issue is that the tray item itself is too generic (limited details + unclear context), so members have lower confidence/intent to tap at the moment of interruption — reducing RSVP conversion.

In the absence of this fix, users are…

Receiving the notification, tapping through to the event detail page, and either finding their way to the RSVP CTA (extra friction) or dropping off.

Desired outcome

A tray item specific enough to drive confident taps and RSVPs: members see the community name, event name, date/time, and event type chip at a glance, and can RSVP immediately on the event detail page after tapping.

Key findings

Discord surfaces an event embed card on creation showing name, date/time, type, and location — with the RSVP button inline. It also uses a two-stage model: an awareness notification on creation, and a second notification when the event goes live (only to members who clicked "Interested").

LinkedIn is the most content-rich for reminder notifications: event name, date, time with timezone, and which connections are attending. Social proof ("3 people you know are going") consistently outperforms date/time alone for RSVP conversion — but this is only viable for reminder notifications, not the creation one (RSVP count is always zero at creation).

Meetup sends a creation notification with event name + group name immediately, then a full-detail reminder series at 7 days, 1 day, and a few hours before. Crucially, if the event time or location changes, the notification reflects the update — a useful pattern for live stream events where Room links may be finalised close to the date.

Facebook frames the creation notification as an actor-led sentence: "[Organiser] invited you to [Event Name] on [Date]" — naming the human behind the event, not just the fact of it.

UX principle (Smashing Magazine, Jul 2025)

"If you're going to interrupt a user, give them a way to act immediately. Use direct and actionable language — include the specific details that answer: what is happening, why it matters now, and what can I do."

Generic notifications get dismissed. Specific, time-anchored ones get tapped.

What to hold for later

Social proof ("X people are going") is the highest-leverage differentiator — but requires RSVP count at notification-generation time. For the creation tray notification RSVP count will always be zero. Flag as a future enhancement for reminder notifications only.

📝 User Stories

⚙️ Regression — Audience Exclusions (existing behaviour)
The following rules reflect the current implementation and must be preserved unchanged. No new engineering work is required for these:
- Banned members (CommunityUser.status = banned) — do not receive the tray notification
- Deleted / inactive members — users who have left or been removed from the community do not receive the notification
- Event host / creator — does not receive their own event creation notification

UC1: Receive tray notification on event creation

User Story: As a community member, I want to receive a notification tray item when a new event is created in my community, so that I can find and RSVP to it in a single tap.

Value / Rationale: Reduces the path from awareness → RSVP from multiple steps to one.

Preconditions:

  • An event has been created in a community on the network

Entry Point A: Event created in a community the user belongs to

Acceptance Criteria:

Scenario: Tray item created for community members on event creation
  Given a user is an active, non-banned member of a community
  When a moderator creates an event in that community
  Then the user receives a NotificationTrayItem
  And the primary line reads "{{CommunityName}} has event {{EventName}}"
  And the secondary line shows an event type chip followed by the event start date and start time
  And the item displays the community avatar
  And the item is marked as unseen

Scenario: In-person event — event type chip
  Given a moderator creates an IN-PERSON event
  When the tray notification is generated
  Then the secondary line shows an "In-person" chip followed by the event start date and start time

Scenario: Virtual / livestream event — event type chip
  Given a moderator creates a VIRTUAL event
  When the tray notification is generated
  Then the secondary line shows a "Virtual" chip followed by the event start date and start time

Scenario: Public community event — notify entire network
  Given an event is created in a PUBLIC community
  When the tray notification fires
  Then all active, non-banned users in the network receive the notification

Scenario: Private community event — only notify community members
  Given an event is created in a PRIVATE community
  When the tray notification fires
  Then only active, non-banned members of that community receive the notification
