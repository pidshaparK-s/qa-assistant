Close the Live Stream Activation Funnel — before, during, and after the event

💡 Opportunity Brief
- What: Give admins the option to send a push notification when creating an event — targeting either the whole network or community members only — with a configurable template.
- Who it's for: Network admins and community moderators running live stream activations (initially Ulta Beauty).
- Why it matters: The current system fires a tray notification on event creation, but no push notification. Push reaches members who haven't opened the app recently — critical for driving RSVPs before a time-sensitive live stream activation.
- Expected outcome: Higher pre-event RSVP rates; admins can build an audience from outside the app at the moment an event is created.

📋 Release Note

Events: Admin-Triggered Push Notification on Event Creation

When creating an event, admins can now optionally send a push notification to community members or the entire network. The push template (title and message) is configurable in the Admin Console. Group privacy settings are enforced automatically: private community events can only push to community members, not the whole network.

💡 Idea

Add an optional "Send push notification" step to the event creation flow. The admin selects an audience (community members / whole network), optionally customises the template, and sends on creation. Privacy rules are applied automatically based on community type.

Push message pattern (aligned with Notification Tray ticket):

Primary line:   {{CommunityName}} has event {{EventName}}
Secondary line: [EventType chip]  {{EventStartDate}} · {{EventStartTime}}

Example: "Ulta Beauty Community has event Ulta Beauty World Masterclass 2026" / [In-person] 10 Jul 2026 · 7:00 PM

{{EventType}} renders as a pill/chip label: In-person for in-person events, Virtual for virtual/livestream events.

{{EventStartDate}} and {{EventStartTime}} refer to the scheduled start of the event (not send time).

The notification icon displays the community avatar.

💭 Problem Definition

What problem are we solving?

Members who haven't recently opened the app miss new events entirely — the tray notification only surfaces inside the app. Admins running brand-partner live stream activations (e.g. Ulta's masterclass series) need push reach to build RSVP counts before the stream begins.

In the absence of this feature, users are…

Relying on in-app tray notifications, which require the member to open the app. Members who are dormant between events have no external prompt to return.

Desired outcome

Admins can optionally push a targeted notification at the moment of event creation. RSVP counts start climbing before the stream date, giving brand partners a larger, warmer audience.

📝 User Stories

UC1: Console configuration — enable push on event creation

User Story: As a network admin, I want to configure whether a push notification is sent when someone creates a new event in a community, so that networks can opt in/out of event-creation pushes without changing the creation flow.

Value / Rationale: Allows network-level control and reduces accidental pushes while still enabling pre-event RSVP growth for activation-heavy networks.

Preconditions:

  • Admin has access to Admin Console settings
  • Push notifications are enabled for the network

Entry Point: Admin Console → Settings → Push notifications → Event-related events

Push message (copy pattern):

Primary line:   {{CommunityName}} has event {{EventName}}
Secondary line: [EventType chip]  {{EventStartDate}} · {{EventStartTime}}

Example: "Ulta Beauty Community has event Ulta Beauty World Masterclass 2026" / [In-person] 10 Jul 2026 · 7:00 PM

{{EventType}} renders as a pill/chip label: In-person for in-person events, Virtual for virtual/livestream events.

{{EventStartDate}} and {{EventStartTime}} refer to the scheduled start of the event (not send time).

The notification icon displays the community avatar.

Acceptance Criteria:

Scenario: Admin sees event-related toggles
  Given a network admin navigates to Admin Console → Settings → Push notifications → Event-related events
  Then they see a toggle "When someone creates a new event in the community"
  And they see a toggle "Notify whole network for events in public communities"
  And "Notify whole network for events in public communities" is disabled unless "When someone creates a new event in the community" is ON

Scenario: Whole-network toggle depends on event-creation push toggle
  Given "When someone creates a new event in the community" is OFF
  When the admin attempts to turn ON "Notify whole network for events in public communities"
  Then the setting cannot be enabled
  And the UI prompts the admin to first enable "When someone creates a new event in the community"

Scenario: Event-creation push disabled
  Given "When someone creates a new event in the community" is OFF
  When an event is created in any community
  Then no event-creation push notification is sent
  And the standard tray notification still fires to community members per existing behavior

Scenario: Event-creation push to community members
  Given "When someone creates a new event in the community" is ON
  When an event is created in any community
  Then a push notification is sent to all active, non-banned members of that community
  And the push deep-links to the event RSVP page

Scenario: Whole-network push allowed only for public communities
  Given "When someone creates a new event in the community" is ON
  And "Notify whole network for events in public communities" is ON
  When an event is created in a PUBLIC community
  Then a push notification is sent to all network users who have push enabled
  And group privacy settings are enforced automatically

Scenario: Whole-network push not sent for private communities
  Given "When someone creates a new event in the community" is ON
  And "Notify whole network for events in public communities" is ON
  When an event is created in a PRIVATE community
  Then the push notification is sent only to community members
  And no push notification is sent to the whole network

UC2: Member receives push notification and navigates to RSVP

User Story: As a network or community member, I want to tap an event push notification and land directly on the RSVP page, so I can commit to attending in one action.

Preconditions:

  • User has push notifications enabled on their device
  • Admin has triggered an event creation push for an audience that includes this user

Entry Point A: Push notification tapped on mobile device

Acceptance Criteria:

Scenario: Tap navigates to event RSVP page
  Given a user receives an event creation push notification
  When they tap the notification
  Then they are navigated to that event's RSVP page

Scenario: Event deleted before user taps push
  Given an event creation push was sent
  When the event is deleted (isDeleted = true) before the user taps
  And the user taps the push notification
  Then they see "This event is no longer available"
  And they are not shown an error or blank screen

Scenario: Push suppressed by device-level notification settings
  Given a user has disabled push notifications at the device or OS level
  When an event creation push is triggered for their audience segment
  Then they do not receive the push
  And they still receive the in-app tray notification per existing behavior

Scenario: Virtual event — no duplicate push from auto-generated Room
  Given an event is a virtual event (Room auto-generated on creation)
  When the admin sends the event creation push
  Then only ONE push notification is delivered to each eligible user
  And the Room/livestream-creation push notification is suppressed
  [Per existing rule: SDD RSVP to Events & Event Reminders, UC4]

Scenario: Push notification content and icon
  Given an event creation push is sent
  Then the push title reads "{{CommunityName}} has event {{EventName}}"
  And the push body shows an event type chip ("In-person" or "Virtual") followed by the event start date and start time
  And the notification icon displays the community avatar
